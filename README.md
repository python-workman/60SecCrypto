# 60SecCrypto — Мониторинг Цен Криптовалют с Deribit API

Высокопроизводительный асинхронный сервис на базе **FastAPI** и **Celery** для ежеминутного автоматического сбора индексных цен криптовалют (BTC и ETH) с биржи **Deribit** и сохранения их в базу данных **PostgreSQL**.
---

## 🛠 Технологический стек

* **Backend API**: FastAPI (Uvicorn, Pydantic v2, Pydantic Settings)
* **Асинхронный клиент**: aiohttp
* **Очереди и периодические задачи**: Celery (Celery Beat)
* **СУБД и ORM**: PostgreSQL, SQLAlchemy 2.0 (Драйверы: асинхронный `asyncpg` и синхронный `psycopg2`)
* **Менеджер процессов**: Honcho
* **Контейнеризация**: Docker, Docker-compose

---

## 📐 Design Decisions (Архитектурные решения)

При проектировании архитектуры сервиса были приняты следующие оптимизационные решения:

### 1. Инфраструктура: Строго 2 контейнера (Выполнение условий ТЗ)
* **База данных как брокер (SQLAlchemy Transport)**: Чтобы уложиться строго в 2 контейнера и избежать усложнения в виде выделенного Redis, Celery переведен на работу через транспорт очередей `sqla` поверх PostgreSQL. Учитывая частоту задач (1 раз в минуту), это решение минимизирует нагрузку на хост.
* **Менеджер процессов Honcho**: Позволяет внутри одного контейнера приложения (`app`) параллельно запускать и логировать три изолированных процесса: веб-сервер FastAPI, планировщик задач Celery Beat и воркер Celery. Гарантирует корректное завершение работы всех процессов по сигналу от Docker.
* **Оркестрация процессов через Procfile**: Для декларативного описания архитектуры процессов приложения используется файл `Procfile`. В нем жестко разграничены три независимых слоя: `web` (FastAPI на интерфейсе `0.0.0.0` для проброса портов), `worker` (исполнитель задач Celery) и `beat` (таймер-планировщик). Утилита `Honcho` считывает этот файл при старте контейнера, разворачивая полноценную многопроцессорную экосистему внутри одной Linux-среды.


### 2. Слой данных и оптимизация СУБД
* **Разделение сетевых драйверов**: Для API эндпоинтов (FastAPI) используется неблокирующий асинхронный драйвер `asyncpg`. Для задач Celery используется стандартный синхронный пул подключений `psycopg2`. Это полностью исключает конфликты транзакций внутри конкурентных потоков.
* **Индексация для GET-запросов**: В модели базы данных `TickerPrice` создан составной индекс `Index("ix_ticker_timestamp", "ticker", "timestamp")`. Так как выборки API строятся по тикеру и сортируются по дате, индекс гарантирует стабильную скорость работы API.
* **Docker Volumes**: Хранилище СУБД вынесено на именованный волум `cryptosec_postgres_data`, обеспечивая сохранность накопленных исторических данных при перезапуске или удалении контейнеров.

### 3. Интеграция с Deribit API
* **Параллельный неблокирующий сбор**: Сбор котировок BTC и ETH реализован асинхронно через `asyncio.gather`. Использование флага `return_exceptions=True` гарантирует, что сетевой сбой по одной валюте не сломает сбор данных по остальным.
* **Маскировка запросов и Testnet**: В клиенте настроен механизм повторных попыток (Retries) с экспоненциальной задержкой и явной передачей.

## 🚀 Инструкция по развертыванию и запуску

Для запуска приложения на вашем компьютере должен быть установлен и запущен **Docker Desktop**.

### Шаг 1. Клонирование репозитория
```bash
git clone <ссылка_на_ваш_gitlab_репозиторий>
cd 60SecCrypto
```

### Шаг 2. Настройка конфигурации (Файл .env)
Создайте файл `.env` в корневом каталоге проекта и добавьте в него следующие параметры:
```env
DB_USER=postgres
DB_PASSWORD=secret_password
DB_HOST=db
DB_PORT=5432
DB_NAME=deribit_db
DERIBIT_BASE_URL=https://deribit.com/api/v2
```

### Шаг 3. Сборка образов и запуск контейнеров
Запустите команду для автоматической сборки образов, инициализации базы данных и старта всех сервисов в едином терминале:
```bash
docker-compose up --build
```

### Шаг 4. Проверка работоспособности
После успешного запуска интерактивная документация API и веб-интерфейс будут доступны по адресу:
* **Swagger UI (FastAPI)**: [http://localhost:8000/docs](http://localhost:8000/docs)

Подождите 1 минуту после старта, чтобы Celery Beat успел отправить первую задачу и наполнить базу котировками.

## 📡 Документация API эндпоинтов

Все методы используют обязательный query-параметр `ticker` (допустимые значения: `btc_usd`, `eth_usd`).

1. **Получение всех сохраненных данных по указанной валюте (с пагинацией):**
   * **Тип запроса**: `GET`
   * **Путь**: `/api/v1/prices/all`
   * **Параметры**: `ticker` (str), `limit` (int, default=100), `offset` (int, default=0)

2. **Получение последней актуальной цены валюты:**
   * **Тип запроса**: `GET`
   * **Путь**: `/api/v1/prices/latest`
   * **Параметры**: `ticker` (str)

3. **Получение цен валюты с фильтром по дате (в формате UNIX timestamp):**
   * **Тип запроса**: `GET`
   * **Путь**: `/api/v1/prices/filter`
   * **Параметры**: `ticker` (str), `start_timestamp` (int, необязательный), `end_timestamp` (int, необязательный)
